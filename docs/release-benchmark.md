# Overdrive release benchmark

Run `node scripts/release-benchmark.mjs` after dependencies are installed. It records fourteen named scenarios in `artifacts/release-benchmark.json`. Scenarios 6–14 execute isolated regression tests. A green result proves only that the named fixture test passed on this machine; it does not prove a live ChatGPT session, a real model admission, a three-worker browser run, or multi-hour stability. Scenarios 1–5 remain `NOT TESTED` until a person runs them in the installed app and records evidence. A focused run accepts `--scenario <1-14>`.

For live scenarios, use a disposable approved project with a real, initially unfamiliar repository. Save the task text, starting commit, app/extension versions, machine/platform, elapsed time, requested and actually confirmed models, worker count, interventions, retries, failures, recoveries, test/build output, and final commit or patch. Do not record secrets or private conversation text. Use the same project for a real bug diagnosis, a multi-file implementation, a failing-test repair, and a refactor with regression protection. Run tests after each change, check the actual files, and explicitly record `FAIL` or `NOT TESTED` when a step does not complete. For a live three-worker or overnight run, separately verify browser pairing, worker identities, reports, sleep/reconnect behavior, and absence of duplicated side effects. The fixture sampler does not replace that evidence.

The JSON fields deliberately use `null` for facts the regression runner cannot observe. In particular, its model and worker fields must not be interpreted as provider-admission evidence. Keep live-run results in a separate dated record; do not edit fixture results to make a release gate pass.
