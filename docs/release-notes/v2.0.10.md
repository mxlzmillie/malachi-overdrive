## MALACHI OVERDRIVE Windows ARM64 release fix

## 2.0.10

- Keeps the MALACHI OVERDRIVE automatic update system from 2.0.9: Windows and Linux AppImage clients check the trusted repository in the background, verify the platform artifact against `SHA256SUMS.txt`, wait until the laptop and app work are idle, then restart/install automatically.
- Fixes the Windows ARM64 release gate that falsely failed when a GitHub-hosted ARM runner cold-started PowerShell more slowly than the test's previous three-second marker window. The verification still requires the launched PowerShell payload to execute; the bounded allowance is now 15 seconds with a 20-second test ceiling.
- Keeps each packaged client pinned to the GitHub repository that built it. Local builds with no baked release repository continue to fail closed instead of following an unrelated upstream release channel.
- Keeps the packaged Chrome companion materialized into its stable user-data folder during app startup so desktop updates refresh the companion files automatically.

### Downloads

- `MALACHI-OVERDRIVE-Setup-x64.exe` — Windows x64
- `MALACHI-OVERDRIVE-Setup-arm64.exe` — Windows on Arm
- `MALACHI-OVERDRIVE-macOS-x64.dmg` · `MALACHI-OVERDRIVE-macOS-x64.zip` — macOS Intel
- `MALACHI-OVERDRIVE-macOS-arm64.dmg` · `MALACHI-OVERDRIVE-macOS-arm64.zip` — macOS Apple silicon
- `MALACHI-OVERDRIVE-Linux-x64.AppImage` · `MALACHI-OVERDRIVE-Linux-x64.deb` — Linux x64
- `MALACHI-OVERDRIVE-Linux-arm64.AppImage` · `MALACHI-OVERDRIVE-Linux-arm64.deb` — Linux ARM64
- `MALACHI-OVERDRIVE-Extension.zip` — standalone Chrome companion extension
- `MALACHI-OVERDRIVE-Native-Sources.tar.gz` — native image-library sources, dependencies, notices and build/replacement instructions
- `SHA256SUMS.txt` — SHA-256 checksums

The native source download accompanies the installers and is covered by the release checksums.
Installed notices link to it and explain the LGPL/MPL components and library replacement.

> **macOS:** publisher-unsigned and unnotarized in 2.0.10; verify the checksum. Requires macOS 13 Ventura or newer. Automatic macOS replacement remains intentionally disabled until releases have a stable Developer ID signature and notarization, because changing ad-hoc code identity can invalidate Accessibility and Screen Recording consent.
> **Linux:** use the AppImage for zero-manual self-updates. The `.deb` remains owned by the system package manager and therefore does not replace itself silently. Where unprivileged user namespaces are disabled, the AppImage launcher can fall back to `--no-sandbox`.

Core and the workspace support Windows, macOS and Linux. Desktop screen/input control is available on Windows and optionally macOS with Screen Recording and Accessibility permissions. External plugins run with their own OS or service permissions and do not inherit approved-folder restrictions. Hosted-service terms and account limits apply. This project remains beta.
