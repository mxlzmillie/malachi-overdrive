## 2.0.11 — MALACHI OVERDRIVE overnight stability

This is a **stability-only release** focused on keeping long multi-agent runs truthful and alive. It does not add a new product surface and it does not include the separate macOS Developer ID signing work.

- Fresh MALACHI OVERDRIVE installs now expose **three worker slots**. Existing/migrated configs keep their saved worker limit; this release does not silently widen an older user's policy.
- Explicit worker model choices are now an admission contract. Before any worker tab opens, MALACHI OVERDRIVE checks ChatGPT's account-observed model catalog. A request for GPT-6 Pro/Astra must be positively present in the current account picker with Pro effort; otherwise the entire multi-worker spawn fails with `MODEL_UNAVAILABLE` and **zero workers are created**. There is no silent fallback to another model.
- The legacy GPT-6 family request `6` + Pro is canonicalized to the exact worker execution alias `gpt-6-pro`, while unrelated/future provider model IDs stay opaque.
- A three-worker overnight run can therefore request **two explicit `gpt-6-pro` / Pro workers plus one independent verifier** and gets all three or none. Tests cover that atomic contract through the real `agents` MCP endpoint.
- An already-admitted Pro/Astra worker that hits ChatGPT's visible **“Too many requests / temporarily limited access / wait a few minutes”** notice now stays in the same redeemed worker tab and waits for that exact notice to clear. It retries model confirmation in place and sends once. It does not open another tab, change model, or permanently kill the worker on a temporary provider throttle.
- The longer bootstrap allowance is Pro-specific and page-owned: an unredeemed worker still fails quickly, ordinary workers keep their existing bounded deadlines, and a redeemed Pro worker remains bounded rather than becoming an endless background process.
- Existing worker recovery, durable inboxes, sleeping-worker reuse, context ceilings, exact request-id ownership, tab-recovery fences and user Stop behavior remain unchanged.

The native source download accompanies the installers and is covered by the release checksums.

> **macOS:** publisher-unsigned and unnotarized in 2.0.11; verify the checksum. Requires macOS 13 Ventura or newer. Automatic macOS self-replacement remains intentionally disabled until the separate Developer ID signing/notarization work is completed, because changing ad-hoc code identity can invalidate Accessibility and Screen Recording consent.
> **Linux:** use the AppImage for zero-manual self-updates. The `.deb` remains owned by the system package manager. Where unprivileged user namespaces are disabled, the AppImage launcher can fall back to `--no-sandbox`.

Hosted-service model availability and rate limits remain controlled by ChatGPT. MALACHI OVERDRIVE now verifies availability and handles temporary Pro throttles without pretending a model is available when the account does not expose it.
