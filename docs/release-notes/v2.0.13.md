## 2.0.13 — MALACHI OVERDRIVE model-truth stability

This is a **stability-only patch** for long-running / overnight / 24-7 multi-agent work. It does not add a new product surface, visual redesign, endless Loop behavior, or the separate macOS Developer ID signing work.

- Windows ARM64 release verification now synchronizes on the real Goal and PluginManager lifecycle events instead of assuming those asynchronous transitions finish inside a one-second polling window. The assertions remain strict: a slow credential startup must stay blocked while its ready peer becomes usable, the peer must execute a real tool call, and shutdown must retire its process.

- MALACHI OVERDRIVE now requires a **fresh ChatGPT account-picker observation for every newly admitted explicit worker model/reasoning selection**. A model catalog restored from an earlier app run is useful for UI continuity, but it is no longer authority to launch new work.
- A request for **GPT-6 Pro/Astra** therefore succeeds only when the current signed-in account positively exposes that exact Pro selection at spawn time. If the fresh picker cannot prove it, the entire staged spawn fails with `MODEL_UNAVAILABLE`, **zero workers are published**, and no worker browser tab is opened. There is no silent downgrade to Sol, another GPT model, or the account default while the broker still claims GPT-6.
- The intended three-worker overnight pattern remains supported atomically: **two explicit `gpt-6-pro` / Pro workers plus one independent verifier** fit the fresh-install three-slot limit. Either every explicit selection is account-proven or none of that staged group starts.
- Regression coverage now proves that a previously valid GPT-6 catalog cannot survive an account/session change as launch authority: if the fresh observation is Sol-only, the old GPT-6 evidence is rejected before browser side effects.
- Fresh spawn admission is serialized through model proof and the durable commit boundary. An unvalidated staged spawn from one prime can no longer leak into another prime's successful snapshot during a concurrent call.
- Every worker/revival command now carries the app's absolute lease deadline into the browser. Hidden or suspended tabs recheck that deadline before Send; waking after expiry produces zero Send rather than late work outside broker authority.
- Exact model proof stays mounted through the worker Send boundary and is rechecked immediately before dispatch. A picker/account selection that drifts after confirmation therefore fails closed instead of journaling GPT-6 Pro while another lane executes.
- Sleeping workers retain their requested model/reasoning identity on revival and re-prove it before new work is sent, so an Astra worker cannot silently wake under a different ChatGPT selection.
- After an app restart, a previously `active` worker restores as detached until its exact chat produces fresh page/turn/tool evidence. If both browser and server-side activity are gone, the existing detached-silence policy frees the slot instead of leaving an orphan active forever.
- Dormant families with unread broker messages are not TTL/capacity-pruned. Worker results remain durable until the owning prime actually acknowledges them.
- The 2.0.11 long-run protections remain intact: temporary Pro access limits wait in the same redeemed worker tab, Pro bootstrap time is bounded rather than endless, worker messages and bindings are durable, sleeping workers remain reusable, tab-loss/revival is fenced by exact conversation identity, and context ceilings prevent unbounded worker-history reuse.
- Chrome revival already fails closed when its live tab scan is unavailable: “could not inspect current tabs” is not interpreted as “the worker chat is absent,” preventing a transient browser API failure from granting duplicate-tab opening authority.

The native source download accompanies the installers and is covered by the release checksums.

> **macOS:** publisher-unsigned and unnotarized in 2.0.13; verify the checksum. Requires macOS 13 Ventura or newer. Automatic macOS self-replacement remains intentionally disabled until the separate Developer ID signing/notarization work is completed, because changing ad-hoc code identity can invalidate Accessibility and Screen Recording consent.
> **Linux:** use the AppImage for zero-manual self-updates. The `.deb` remains owned by the system package manager. Where unprivileged user namespaces are disabled, the AppImage launcher can fall back to `--no-sandbox`.

Hosted-service model availability and rate limits remain controlled by ChatGPT. MALACHI OVERDRIVE's guarantee is narrower and testable: an explicit worker model is launched only after the current account picker proves that selection, and temporary Pro throttles never authorize a model substitution.
