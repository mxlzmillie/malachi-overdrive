## 2.0.14 — MALACHI OVERDRIVE Astra completion stability

This is a **stability-only patch** for long-running / overnight / 24-7 multi-agent work. It fixes the live GPT-6 Pro/Astra completion and ChatGPT picker compatibility failures found after 2.0.13; it does not add a new product surface, visual redesign, endless Loop behavior, or the separate macOS Developer ID signing work.

- GPT-6 Pro can expose ChatGPT's exact connector `request_id` only **after** the connector result is returned. In 2.0.13, `agents action=finish` could wait synchronously for that same evidence, creating a circular dependency: the result waited for identity while identity waited for the result.
- `agents finish` now keeps the normal same-tick exact-ID fast path. If ownership is still unavailable, MALACHI OVERDRIVE stores the worker result as a **durable ownerless pending finish keyed only by ChatGPT's exact request ID** and returns promptly. No active-tab state, recent-conversation heuristic, model label, or timing guess may choose a worker.
- When the browser/recorder later proves that exact request ID belongs to one concrete worker conversation, the app atomically commits the worker's sleeping/terminal state, authored result, prime report, and any inbox acknowledgement the finish call itself proves.
- Pending finishes remain inside the existing v6 swarm snapshot as an optional backward-compatible field, so a crash cannot lose the report and an older 2.0.13 build can still read the underlying run topology.
- Duplicate late-correlation callbacks are idempotent: the request is removed from the pending map synchronously before the durable finish commit waits on disk, so a second callback cannot publish the same result twice.
- Regression coverage reproduces the live failure order directly: the finish result returns first, the exact request ID appears afterward, and only then does the correct worker report reach its prime. Restart coverage also proves prior inbox delivery is not falsely reported as unconfirmed.
- ChatGPT picker discovery now begins Fiber-state observation immediately after opening the native model menu instead of first treating the portal DOM node as readiness. This prevents a portal-before-React commit race from returning `picker_unavailable` even though the picker is visibly open.
- Native model version rows now match their **primary model label** rather than full row text, so secondary provider copy such as `Leaving on October 14` cannot turn a valid GPT-5.5/GPT-6 catalog into `model_unconfirmed`.
- The 2.0.13 model-truth rules remain unchanged: every newly admitted explicit worker model/reasoning selection still requires a fresh signed-in ChatGPT picker observation, GPT-6 Pro/Astra is never silently substituted, and an unavailable requested model fails the staged spawn atomically with zero workers published.

The native source download accompanies the installers and is covered by the release checksums.

> **macOS:** publisher-unsigned and unnotarized in 2.0.14; verify the checksum. Requires macOS 13 Ventura or newer. Automatic macOS self-replacement remains intentionally disabled until the separate Developer ID signing/notarization work is completed, because changing ad-hoc code identity can invalidate Accessibility and Screen Recording consent.
> **Linux:** use the AppImage for zero-manual self-updates. The `.deb` remains owned by the system package manager. Where unprivileged user namespaces are disabled, the AppImage launcher can fall back to `--no-sandbox`.

Hosted-service model availability and rate limits remain controlled by ChatGPT. MALACHI OVERDRIVE's guarantee is narrower and testable: an explicit worker model launches only after the current account picker proves that selection, and a delayed finish publishes only after ChatGPT's exact request ID proves the worker conversation.
