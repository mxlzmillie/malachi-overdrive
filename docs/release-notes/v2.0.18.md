## 2.0.18 — provider compliance + release hardening

This beta release hardens provider boundaries, local bridge security, preview authorization, startup resilience and the MALACHI OVERDRIVE operating surface without removing the local engineering capabilities that make the workbench useful.

- **Provider limits are respected explicitly.** Goal/Loop treats provider HTTP 429 rate limits and durable client-side access/account failures as visible, non-auto-retry boundaries. It still recovers from genuinely transient transport, 408/425 and 5xx failures. A provider refusal is never turned into account rotation, identity rotation, quota-reset behavior or an automatic attempt to defeat enforcement.
- **Model truth stays fail-closed.** Explicit worker model/reasoning requests still require a fresh ChatGPT account-picker observation before worker publication. If the requested model is unavailable, the spawn fails instead of silently substituting a different model while displaying the requested one.
- **Packaging backoff is provider-aware.** Native-source download retries remain finite and checksum-bound; HTTP 429 honors `Retry-After` and otherwise waits at least 15 seconds before the next bounded attempt.
- **Companion pairing is stronger.** Bridge protocol 14 requires the rotating pairing code shown in the desktop app, so a local caller cannot obtain a browser token merely by finding the loopback port. The matching extension is required after this update.
- **Project previews re-check authority.** Preview URLs are unguessable and every request re-validates the current approved-folder/read capability, so revoking access also cuts off already-open preview links.
- **Startup no longer hangs indefinitely on credential probing.** Initial OS credential-store checks are bounded; the renderer can load and show actionable recovery guidance when macOS Keychain access is waiting on the OS.
- **Control Rail is the current operator surface.** The previous agent panel is removed in favor of the Control Rail projection. Partial startup state, including a missing bridge snapshot, is displayed as unknown rather than crashing the session list.
- **Terminal regression coverage is scheduler-tolerant.** The completed pipe-command parity test now gives a fresh child enough bounded time to start, emit stdout/stderr and report its real non-zero exit under a saturated parallel run, without changing production terminal timing.

### Validation

Before tagging this release, the shared working tree completed `npm run verify` successfully: 141 ordinary suites passed with 3,482 tests passed and 106 skipped, followed by the separate shutdown suite with 2 tests passed. After the final terminal-regression timing adjustment, that same full gate passed again with 3,482 ordinary tests plus the 2 shutdown tests. TypeScript, public-history privacy, third-party notice/native-source validation, `git diff --check`, and the production `npm run build` also passed. The previously failing Control Rail suites passed 15/15, and the completed-pipe regression passed three focused runs in a row before the full green verification.

The local installed ARM64 candidate also completed a harmless fresh-chat delivery check on September 17, 2026: the message was acknowledged and the reply `OVERDRIVE_READY` was visible in the Overdrive UI. This is evidence for ordinary local send/receipt behavior, not a claim that every long-run or provider workflow was exercised live.

### Beta limits

MALACHI OVERDRIVE remains beta. Provider subscriptions, quotas, model availability, access controls and service terms remain controlled by the connected provider. This release does not claim extra provider entitlement or unlimited hosted-model usage.

The full live three-worker/overnight/recovery matrix was not re-proved end to end in this release cycle, and earlier local Compact & Resume dogfood encountered a provider-side replacement-chat error. The release CI still builds and smoke-checks the native platform/architecture matrix before GitHub publication; a red candidate job prevents the release from being created.

> **macOS:** publisher-unsigned and unnotarized in 2.0.18; verify the checksum before installing. Requires macOS 13 Ventura or newer. Automatic macOS self-replacement remains disabled until Developer ID signing and notarization are in place, because changing ad-hoc code identity can invalidate Accessibility and Screen Recording consent.

> **Linux:** the AppImage is the zero-manual-update path. The `.deb` remains owned by the system package manager. Where unprivileged user namespaces are disabled, the AppImage launcher can fall back to `--no-sandbox`.

MALACHI OVERDRIVE itself is local/open-source software; connected hosted providers remain separate services with their own plans, quotas, access rules and terms.
