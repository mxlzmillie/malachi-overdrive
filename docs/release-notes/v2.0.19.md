## 2.0.19 — model-selection truth + signed macOS distribution

This beta patch fixes one exact worker-model handoff bug found while live-testing the current ChatGPT picker and upgrades the public macOS release path to Developer ID signing and Apple notarization.

- **Worker aliases now survive the browser handoff without widening authority.** ChatGPT currently exposes the GPT-5.6 family as family id `5.6` while the observed catalogue can carry execution aliases such as `gpt-5-6-thinking`. A worker request using the account-observed `gpt-5-6` family spelling could pass fresh admission and then fail at browser selection. The picker now resolves only that narrow observed family/lane relationship, while the requested reasoning effort is still checked independently. It does not turn one lane into permission for another lane and it does not introduce a default-model fallback.
- **Astra remains fail-closed.** During release validation the live account catalogue exposed GPT-5.6 Sol and GPT-5.5, but not GPT-6 Pro/Astra. Explicit Astra workers therefore continue to fail with `MODEL_UNAVAILABLE` rather than silently running on Sol. This release improves selection correctness; it does not claim or manufacture provider entitlement.
- **macOS public artifacts are Developer ID signed.** Release packaging requires a `Developer ID Application` identity and refuses to publish if signing credentials are missing. The app and its nested Electron binaries are signed coherently under the same Team ID, avoiding the mixed-Team library-validation failure reproduced during the earlier manual-signing experiment.
- **macOS public artifacts are notarized by Apple.** Release CI uses App Store Connect API-key notarization credentials and fails closed when the credential triplet is incomplete. Local development packaging still uses the existing coherent ad-hoc seal so contributors do not need Apple credentials.

### Validation

Before release preparation, the focused model catalogue and picker suite passed 36/36 tests. The targeted worker/bootstrap/revival selection suite passed 70 tests with the unrelated cases skipped by the focused filter. A live smoke proved `5.6 / high` could start and finish a worker while the equivalent `gpt-5-6 / high` alias failed before this patch, which is the exact regression covered here. The release pipeline also retains strict macOS signature, bundle, GUI-launch and packaging checks and now requires notarization credentials for public macOS builds.

### Beta limits

Hosted model availability remains controlled by the connected provider and account. MALACHI OVERDRIVE does not bypass model access controls, quotas or temporary provider restrictions. A requested model that is not present in the fresh account picker remains unavailable.
