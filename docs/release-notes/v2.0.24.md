## 2.0.24 — Free Goal/Loop models and background reliability

Goal and Loop can use Kilo's anonymous free-model gateway without an account or API key. Settings
provides one explicit activation button that first checks for a currently free model with the
structured text output Goal/Loop needs. The main process checks the selected model's free status
again before each completion request and refuses an unknown or newly paid model before sending
conversation text. It does not switch to a paid model or another provider automatically.

This cloud option sends recorded conversation text to Kilo and its model provider. If tool details
are enabled, recorded tool arguments and results go there too. The activation screen explains that
free providers may retain or train on prompts, links to Kilo's terms and privacy policy, and warns
against using the option for private or confidential work. Kilo's anonymous IP rate limits and
free-model availability can change; no unlimited use or permanent free access is promised. The
main ChatGPT model selection remains independent.

Settings also shows compatible OpenRouter models whose current catalogue prices are explicitly
zero. Browsing that list needs no key, but using an OpenRouter model for Goal or Loop still needs
the person's OpenRouter key. The linked Awesome Free Models repository is a reference list, not
an inference service.

This release carries forward the unpublished 2.0.23 browser changes:

- Revealing one task moves only its exact tab; sibling tasks stay isolated and continue working.
- The companion popup can reconnect a selected idle, draft-free task chat after a browser restart
  without opening a duplicate or replaying an uncertain send.
- App-owned tab bookkeeping remains stable through long helper-tab churn. Quiet task tabs and
  finished empty helpers retire only after fresh document and no-draft/no-generation proof.
- The Windows UI Automation release test accepts the host provider's actual control role while
  still checking exact control identity and a negative role case.

### Validation and release gates

The source verification suite, production bundle, packaged-runtime checks and the six native
candidate jobs are release gates. Candidate assembly requires both Windows NSIS packages to
install and launch normally, Developer ID signing and Apple notarization for both macOS
architectures, and checksum coverage for every payload beside `SHA256SUMS.txt`. Publishing at
the reviewed version tag rebuilds the artifacts from that tag and verifies the exact 13-asset
set and every public download digest. The official signed ARM64 build must still be installed
and opened separately before calling the local update complete.

- `MALACHI-OVERDRIVE-Native-Sources.tar.gz` — corresponding native sources, notices and build instructions
- `SHA256SUMS.txt` — SHA-256 checksums

Public macOS artifacts require Developer ID signing and Apple notarization for both architectures.
They preserve the existing bundle identifier and signing team. macOS 13 Ventura or newer is
required. Reload the matching protocol-15 browser companion after updating; existing pairing is
preserved.

Linux AppImage installations use the bundled static runtime. Where unprivileged user namespaces
are disabled, that runtime can fall back to `--no-sandbox`. The `.deb` stays under the system
package manager's control.

Model admission remains fail-closed. An unavailable model or reasoning level is reported rather
than silently substituted.
