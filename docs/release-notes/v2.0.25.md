## 2.0.25 — Isolated Opera window recovery

When Opera Air creates a private ChatGPT window, its first response can omit the tab, report the
window as normal before minimization finishes, or briefly expose a blank URL. MALACHI OVERDRIVE
now waits for a fresh exact tab and minimized, unfocused window proof before claiming that surface.
It makes at most one guarded minimize request for an unfocused first window. If proof still fails,
the companion remembers the provisional window across worker suspension and blocks another
placement until that window closes; retries cannot accumulate new unconfirmed windows or adopt a
surface that may have been revealed. A failed window is closed during the original attempt only
after its pinned document proves it is idle and has no draft or generation.

The message for an unsent new chat now says that Opera could not confirm a private background
window and explains how to clear a stalled window if a retry cannot proceed. An existing task with lost isolated custody still requires explicit
reconnection from its exact ChatGPT tab. Neither case silently replays an uncertain send or adopts
a personal tab.

### Validation and release gates

Focused browser ownership and desktop-input regressions, source verification, production build,
packaged-runtime checks and six native candidate jobs gate this release. Public macOS builds
require Developer ID signing and Apple notarization for both architectures. Publishing from the
reviewed tag rebuilds and verifies all 13 artifacts and their public SHA-256 digests. Install and
open the signed ARM64 build separately before calling the local update complete.
