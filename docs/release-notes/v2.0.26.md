## 2.0.26 — Isolated Opera window recovery

Opera Air can return a newly created ChatGPT window before its tab, URL or minimized state is
fully visible. MALACHI OVERDRIVE now waits for a fresh single-tab, exact-URL, minimized and
unfocused proof before handing it a message. It makes at most one guarded minimize request,
only after a fresh query confirms the sole tab. Temporary browser API errors do not mean a
provisional or already-owned window closed.
Brief empty-tab and normal/unfocused reads of an owned window also wait instead of opening
another background window.

If a first-window proof still fails, the companion pins that physical window across worker
suspension. Later inputs cannot open more windows or adopt its uncertain history. Chrome's
confirmed window-removal or whole-window tab-close event clears provisional and owned IDs when
a window really closes. If the tab hydrates after a failed attempt, a later placement may retire
that exact unchanged document only
after a no-draft/no-generation page proof, then open one replacement. Revealing a window revokes
automatic custody across companion suspension; live operation markers cannot override that.
New chat failures report that the message was not sent and explain how to clear a stalled window.
An existing task with lost custody still requires explicit reconnection from its exact chat.

The unpublished 2.0.25 tag was canceled during candidate review and has no GitHub release;
these changes include and complete that candidate.

### Validation and release gates

Focused browser ownership and desktop-input regressions, source verification, production build,
packaged-runtime checks and six native candidate jobs gate this release. Public macOS builds
require Developer ID signing and Apple notarization for both architectures. Publishing from the
reviewed tag rebuilds and verifies all 13 artifacts and their public SHA-256 digests. Install and
open the signed ARM64 build separately before calling the local update complete.
