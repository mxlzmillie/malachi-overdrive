## 2.0.27 — Replacement helper recovery

An ambiguous helper delivery could leave **Start a new helper** visible after the app restarted,
but the click only retired the old cancellation record. It did not create a replacement helper,
leaving the task stuck.

MALACHI OVERDRIVE now creates one new isolated helper with a fresh delivery identity after that
explicit user action. The old helper remains a terminal record and cannot complete on behalf of
the replacement. The replacement preserves its source context, does not automatically type back
into the original ChatGPT conversation, and records its result in the source task's local history.
For account-restriction recovery, the replacement is explicitly instructed not to send or retry
email outreach.

### Validation and release gates

Focused browser-decision and Goal retry tests cover both in-memory retries and restart recovery;
TypeScript validation and the production build also pass. The public release pipeline rebuilds all
target artifacts, validates their SHA-256 digests, and runs native package smoke tests. Public
macOS builds require Developer ID signing and Apple notarization for both architectures before
publication.

### Linux launcher note

On Linux systems that disable Chromium's unprivileged user namespaces, launch the AppImage with
`--no-sandbox`. This is required for compatibility with those host policies.
