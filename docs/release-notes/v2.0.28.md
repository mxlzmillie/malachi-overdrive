## 2.0.28 — Historical helper restart repair

Some tasks created by an older MALACHI OVERDRIVE release contained a terminal marker saying that
the user had authorized a new helper, but no replacement helper had actually been created. That
could leave the source task without the **Start a new helper** action after an upgrade.

This release recognizes only that exact historical marker when it is the newest decision for the
task and no newer helper exists. It then permits one new isolated helper. Any later decision,
including a completed helper, permanently closes the repair path so the action cannot create
duplicate work. The replacement helper carries the existing no-outreach restriction: it may review
the account notice and report the next permitted recovery step, but must not send or retry email
outreach.

### Validation and release gates

The focused durable session-input suite covers the historical recovery path, normal Goal retries,
and the no-duplicate fence. TypeScript validation and the production build also pass. The public
release pipeline rebuilds every target artifact, validates SHA-256 digests, and runs native package
smoke tests. Public macOS builds require Developer ID signing and Apple notarization for both
architectures before publication.

### Linux launcher note

On Linux systems that disable Chromium's unprivileged user namespaces, launch the AppImage with
`--no-sandbox`. This is required for compatibility with those host policies.
