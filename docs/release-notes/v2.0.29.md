## 2.0.29 — macOS workspace startup repair

On macOS, an in-place application update could leave Electron to infer its profile directory from
LaunchServices. That inference could select a transient profile at startup, causing the app to exit
without restoring its existing MALACHI OVERDRIVE window, workspace, bridge, or helper controls.

The app now selects its established `chat-on-steroids` workspace path before Electron acquires its
single-instance lock. This keeps the launch identity, saved workspace, bridge credentials, browser
companion state, and durable task state aligned across updates.

### Validation and release gates

The targeted durable session-input suite, version-parity packaging tests, TypeScript validation, and
the production build pass. The public release pipeline rebuilds every target artifact, validates
SHA-256 digests, and runs native package smoke tests. Public macOS builds require Developer ID
signing and Apple notarization for both architectures before publication. macOS 13 Ventura or newer
is required.

### Linux launcher note

On Linux systems that disable Chromium's unprivileged user namespaces, launch the AppImage with
`--no-sandbox`. This is required for compatibility with those host policies.
